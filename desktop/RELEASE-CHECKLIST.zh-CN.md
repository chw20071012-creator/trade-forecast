# Windows 桌面版发布复盘与检查顺序

本记录针对 0.2.0 桌面化过程；先判明失败位置，再修改和提交。不能把编译成功、某个步骤成功或取消的整轮检查视为完整发布通过。

## 已查明的失败

| 失败位置 | 原因与证据 | 修正 |
| --- | --- | --- |
| Windows 打包脚本输出 | 控制台默认编码不能处理中文路径 | 工作流 Python 命令统一显式使用 `-X utf8`；脚本以 UTF-8 保存，PowerShell 5.1 脚本带 BOM |
| 原生依赖导入检查 | 扫描进入 greenlet 的开发测试组件，错误要求可选 psutil | 排除明确的上游 test/tests 和 _test 模块；仍导入全部 30 个生产原生扩展，并对关键扩展逐项断言 |
| 端口占用弹窗测试 | 实际控件文本为 OK、ID 为 2，测试误假定 ID 为 1 | 等待子控件完成创建；匹配预期警告内容及唯一可见按钮；保留独占端口与原进程存活断言 |
| PowerShell 5.1 安装 | 当前 Windows 测试环境未能加载 Get-FileHash；继承 pwsh7 模块环境是可能原因，尚未单独证明 | 改为 .NET SHA256 流式校验；保留每个文件的完整性检查，避免依赖模块自动加载 |
| Unicode 快捷方式创建 | Windows 实测失败行是 WScript.Shell 的 TargetPath 赋值，HRESULT E_INVALIDARG；与 GitHub 同类报告一致 | 用原生 IShellLinkW / IPersistFile 宽字符接口，测试独立读取宽字符目标与工作目录，不改成 ASCII 路径逃避检查 |
| 快捷方式回归检查的路径比较 | Shell 读取返回 runneradmin 长目录名，测试临时目录使用 RUNNER~1 短名称，字符串比较误报；中文部分已正确保留 | 核对实际文件/目录身份，同时保留目标、工作目录和图标检查 |
| Windows SQLite 生命周期复核 | SQLite 上下文管理器不会自动关闭连接，可能阻止改名/迁移 | 明确关闭数据库连接，保留提交语义；已有回归验证 |
| 安装目录命名复核 | 秒级时间戳可能让并发安装重名 | 时间戳加 GUID；目录移动遇到已存在目标直接失败，避免嵌套 |

## 下次提交前

1. 明确改动属于产品、打包还是测试脚本。保存具体错误、失败步骤与环境，不根据红色状态猜原因。编译、打包命令也必须将具体失败输出附到检查注释；不得只有泛化退出码。
2. 在本机完成适用的语法、单元与打包检查；已经通过且不受新改动影响的检查不反复扩大。
3. 保留中文和空格路径；使用与用户一致的 Windows PowerShell 5.1；不要把 Linux 或 PowerShell 7 解析成功说成 Windows 安装通过。
4. 打包时复核官方运行时/依赖校验和、清单中每个文件的 SHA256、ZIP CRC，排除真实客户数据、令牌、缓存和本机目录。
5. Windows 检查分别验证源码构建包与最终下载 ZIP。检查原生依赖、HTTP 就绪、迁移、重复启动、正常退出、占端口保护。
6. 从实际“安装到桌面.cmd”验证复制、快捷方式、自动启动、退出和既有数据保留。测试数据隔离；仅清理测试拥有的进程；恢复原快捷方式。
7. 遇到失败先阅读具体日志或注释；至少有新的诊断证据或已验证的修正，才重新提交。不能通过删断言、取消检查或隐藏报错制造通过状态。
8. 完整 Windows 检查通过后，核对公开下载文件的长度与 SHA256，再发布说明和下载链接。明确账号授权与用户本机网络仍需配置。

## 发布依据

安装错误已经定位到 WScript.Shell 设置中文目标路径。每次正式交付都应以对应提交的完整 Windows 安装检查结果为依据，发布页应提供实际通过的检查链接及最终下载包校验和。静态复核与 Linux 交叉编译不能代替 Windows 执行结果。

参考问题：[非 ASCII 路径下 WScript.Shell 快捷方式 E_INVALIDARG](https://github.com/Rice-dog/code-codex/issues/59)。该报告只作为定位线索；本项目以自己的失败行和回归测试验证结论。
