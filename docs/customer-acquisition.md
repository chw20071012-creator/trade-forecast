# 多来源客户开发设计

状态：已实现获客采集、公开官网补充、资料导入、去重、来源记录和分段进度，离线逻辑及本地浏览器演示已验证。真实 Google Maps 有限探测以 `paused_search_error` 暂停，错误为 `net::ERR_TUNNEL_CONNECTION_FAILED`，没有完成真实客户采集；其他平台与付费联系人服务未宣称接通。用户通过 ChatGPT 指令或本地网页触发，不定时运行。

## 流程

用户产品目录/关键词 → 官方汇总统计与国家机会分析 → 用户选择国家 → 多来源发现公司 → 去重与买家匹配 → 公司画像 → 关键联系人定位 → 工作联系方式补充与验证 → 邮箱/WhatsApp 触达草稿 → 按已确认的渠道执行方式发送 → 发送与回复记录。

## 搜索与客户分类

- 箱包 OEM：重点比较品牌商、进口商、批发商、专业设备客户的匹配度；制造商是否可能外包或采购需结合产品及官网事实判断。
- 茶叶 B2B：比较进口商、茶叶品牌、批发商、分销商、餐饮/茶饮客户的匹配度。
- `manufacturer` 只是分类关键词之一，不统一作为所有产品的默认买家标签。
- 可组合产品词、买家类型、国家/地区、`catalog`、`filetype:pdf`、`site:` 等查询；国家域名不是公司所在地的充分证据。
- 参展身份仅证明行业相关性；公司画像必须判断采购关系。

## 小商户与执行批次

- 箱包除品牌商和进口商外，寻找箱包零售店、礼品店、小型批发商及有真实采购需求的个体经营商；茶叶增加茶叶店、咖啡/茶饮店、餐饮经营者及专门食品商店。商户类别只用于发现线索，采购匹配仍需证据。
- 不以企业规模、是否自有官网、订单量小作为一票否决。以产品适配、预计订单利润、履约能力和真实供货条件决定开发优先级；金额未知时保留待核实，不假定已经盈利。
- 盈利评估计入采购、包装检测、运输、支付/收款、汇率及可估算的沟通服务成本；检查 MOQ、小批量生产和实际交期。需要低 MOQ 或其他供货方式时提出建议，不凭空宣称供应商可以执行。
- 程序按免费额度与客户质量提出单批数量，由用户确认。合格线索不限于该批次，保留后续队列；按国家、城市/地区、商户类型、当地语言关键词保存查询和覆盖进度，用户再次指令时可以续做。
- Maps 没有邮箱时继续访问公开商户官网和可用业务页面。公开电话号码不直接视为 WhatsApp 账号；联系方式未知的商户保留待补。第 24 问已选择邮箱与 WhatsApp 触达；第 25 问已确定生成消息和聊天链接，由用户打开并发送。
- 记录查询返回与访问失败，不能承诺穷尽全部客户。不同门店与总公司关联但不一概合并；拒绝继续联系、退订或不匹配的主体保留状态，避免反复开发。

## 公司画像与关键联系人

- 画像字段：法人/品牌名称、国家、官网、主营产品、渠道、公司类型、采购证据、规模线索、适配产品、待核验事项。
- 候选岗位：Procurement/Purchasing/Sourcing、Buyer、Supply Chain、相关产品负责人；小公司可增加 Owner/Founder/Managing Director。
- Manager/Director/Executive 是职位线索，需结合部门和实际职责判断采购相关性。
- LinkedIn、公司官网与查询平台结果关联到具体公司和岗位；同名个人不直接合并。
- 客户痛点标为“有证据”或“假设”，个性化邮件不能将假设写为已确认事实。

## 联系方式与数据处理

- Hunter、Lusha、RocketReach、Apollo 为后续可选接入，首版未配置或验证这些 API；当前可导入合法获取的名单，并从公开官网补充业务联系方式。
- 用户允许按需提供账号或更换方案。接口可替换，不把所有工具都设为硬性依赖；第 20 问已确定先免费，需要收费能力时说明费用并另行讨论。
- 平台网页或插件功能不自动等于可供程序调用的 API 功能。未提供权限时支持导入用户合法取得的导出数据。
- 优先整理工作邮箱与业务联系方式；首版触达范围已确定为邮箱与手动 WhatsApp，LinkedIn 只作为负责人发现来源。
- 每条联系方式保留来源、取得时间、联系人岗位、验证结果和置信度。域名 MX 存在不等于具体邮箱可投递。
- 去重综合域名、规范化公司名、国家、联系人和邮箱；保留多来源证据及存在歧义的主体关系。
- 搜索失败、记录缺失、权限/额度不足、邮箱未知均单独保存状态，不伪造结果或把未核验当通过。

## 触达与反馈

- 产品和供应商实际资料用于生成与客户有关的邮件，引用的认证、价格、产能、交期须有依据。
- 每封邮件围绕该客户实际业务、产品适配与采购角色定制，不以替换名称代替个性化；保留所用事实的来源和未核实项。
- 邮件先生成待审版本，用户确认该版本后发送；内容或收件人修改后，该确认失效。
- 第 26 问选择批量审核：展示客户名单、每封完整内容及附件，用户选择具体草稿后一次确认。各邮件分别发送，采用可配置间隔、账户限额检查及异常暂停，详见 `outreach-delivery.md`。
- 记录发送、退信、回复、询盘、成交和下次跟进建议；不因“没有回复”推断邮箱无效或客户没有需求。
- 第 27 问允许读取整个企业邮箱，自动识别外贸相关邮件，包括尚未建档的新客户询盘。用户指令触发同步，按邮件/线程标识去重并保存同步进度；外部邮件正文与附件视为待分析资料，不能作为越过用户发送确认的指令。
- 首版触达渠道为邮箱与 WhatsApp。LinkedIn 用于查找负责人；其他社交平台未选为首版发送渠道。
- WhatsApp 采用生成消息及聊天链接的手动方式，用户打开后点击发送。号码规范化为国际格式并保留来源；无有效号码时标记待补。首版不以商业发送 API 为依赖。
- 生成消息、打开聊天和实际发送分开记录；手动方式不能仅凭打开聊天就标记已发送，程序发送方式以可用的接口响应核对。WhatsApp 发送不默认继承邮箱草稿的确认。

## 首次真实使用

已确认结构化导入主格式为 XLSX、CSV 兼容；原文件作为补充资料保留。生产、物流、收款及售后进度由用户录入/上传或从邮件提取，确认后更新。邮箱读取范围为整个企业邮箱，草稿逐封定制、逐批审核和间隔发送；WhatsApp 由用户手动发送并确认记录。预算先免费，利润底线及每批数量均由程序建议、用户确认。首次使用按 `QUICKSTART.zh-CN.md` 安装浏览器、导入真实资料、选定国家并验证网络；浏览器可以尝试已安装的 Chrome/Edge，未下载 Chromium 不标为下载成功。
