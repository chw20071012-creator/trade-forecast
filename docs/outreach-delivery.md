# 邮件与 WhatsApp 触达执行设计

状态：已实现 Gmail OAuth/读取/发送适配、定制草稿、版本绑定批量审核、间隔和额度控制、暂停/续做、发送结果核对以及 WhatsApp 手动链接与状态记录；离线测试和本地浏览器演示已通过。Gmail OAuth 尚未配置，没有读取真实邮箱或发送真实邮件。2026-10-11 检查官方规则页面时均被当前云环境网络代理以 `Tunnel connection failed: 403 Forbidden` 阻断；未核实现行数值、实际账户权限或是否适用试用账户限制。此结果不是官方平台拒绝用户。

首次授权、签名、发送限额和规则审核在本地网页配置，步骤见 `QUICKSTART.zh-CN.md`。默认演示模式；真实发送要求实际账号授权、规则审核及具体草稿版本批准同时成立。默认日限额 20、单批上限 20、最小间隔 120 秒只是可修改的保守运行设置，不是 Google 官方额度。

## 个性化与批量确认

- 每封开发信单独生成，使用客户真实业务、采购角色、产品适配和来源明确的事实；事实不足时标出缺项，不制造痛点、进口量、产品认证和供货承诺。
- 展示本批客户与每封完整邮件、收件人和附件，用户选择需要发送的草稿并一次确认。每封保持独立收件人，不将客户名单暴露在群发收件栏。
- 确认绑定不可变的草稿版本、收件人和附件摘要；编辑后确认失效。发送队列只包含本次已确认的具体版本。

## 发送节奏与限额

- 按实际账户类型核实邮件数量、收件人数、外部收件人等适用限额与统计窗口；API 请求配额单独处理，不把 API 额度当邮件额度。
- 发送间隔、单批上限和账户观察期配置可修改，具体数值须在实际部署时核实。平台公布的最大配额不作为开发信的建议发送量；不存在保证账号安全的固定间隔。
- 基于本地持久化发送记录计算限额；邮件客户端及其他程序发送的邮件也可能占用账户配额，本程序记录不能代表账户全部已用量。账户配额无法完整读取时保留余量并显示估计状态。
- 排队、等待间隔、暂停与继续仅属于用户发起的任务；不新增自主定时开发。电脑关闭或连接中断后保存进度，避免整批重发。
- 权限/配额错误、账号警告、异常退信或发送结果不明确时暂停相应任务。当前发送实现不自动重试失败的发送请求；结果不明先核对已发件与持久化 Message-ID，无法确认时由用户核实并记录，再明确指令续做，不能盲目重复发送。平台限制不通过切换账号、代理或无限重试突破。
- 硬退信、明确拒绝继续联系或退订的地址保存停止联系状态；跟进仍生成待审草稿，不自动越过已有确认规则。
- 域名认证、平台发送规则与收件人要求纳入安装配置检查；发送间隔和个性化不能替代这些条件，也不能保证永不封禁。

## WhatsApp

- 首版仅生成个性化消息和有效国际格式号码对应的聊天链接，由用户打开并点击发送。不启用 WhatsApp 商业发送 API 或自动网页群发。
- Google Maps 公开电话不自动证明已注册 WhatsApp。生成链接、打开聊天、实际发送及收到回复分别记录。
- 手动发送同样需核实适用的 WhatsApp 账号及消息规则；不把免费、手动或间隔发送视为无限量联系许可。
- 已实现用户确认 `opened`、`sent`、`replied` 的记录入口，发送来源标为用户报告；打开链接不自动标记已发送，程序没有 WhatsApp 平台送达验证。
